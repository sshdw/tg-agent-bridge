# ТЗ — TG Agent Bridge (v0.1, на утверждение)

## 1. Общее
Telegram-бот на Node 20 + TypeScript strict + grammy + SQLite. Один бот — много ИИ-агентов через `IAgentProvider`. Scope v0.1 — текст + фото + работа с репо.
Назначение: мост между владельцем и агентом, запущенным на домашнем ПК. Бот крутится на ПК, управление — с телефона через Telegram. ПК должен быть включён и в сети.

## 2. Функциональные требования
- FR-1 `/start` отвечает <2с, показывает активного агента.
- FR-2 `/ask <текст>` → задача активному агенту, ответ в тот же чат. Стриминг: живое редактирование сообщения по ходу генерации (как ChatGPT).
- FR-3 `/code <задача>` → то же, но с пометкой `mode: code` (провайдер может добавить системный префикс).
- FR-4 `/agent <id>` переключает провайдера сессии. Неизвестный id → список доступных.
- FR-5 `/model <name>` сохраняет модель в сессии, проксирует провайдеру. Пустой → сброс. Переключение только из ТГ.
- FR-6 `/status` — текущая задача + очередь чата.
- FR-7 `/cancel` — убивает running-задачу чата (SIGTERM subprocess / AbortController HTTP).
- FR-8 Очередь: 1 running на чат, остальные pending в SQLite. После `done/error/cancel` — следующая.
- FR-9 Whitelist: личный бот, `ALLOWED_CHAT_IDS` заполнен id владельца; чужой → игнор без ответа.
- FR-10 Нарезка: ответы >4000 символов режутся на несколько сообщений, код в ``` блоках.
- FR-11 Фото: картинка из чата сохраняется в workdir чата, путь передаётся провайдеру вместе с подписью.
- FR-12 Репо: `/clone <url>` клонирует в `WORK_ROOT/<name>`; `/project <name|path>` привязывает чат к папке проекта (только внутри `ALLOWED_ROOTS`).
- FR-13 Разрешения: `/auto on|off` — выполнять shell-команды агента без подтверждения или спрашивать (`/approve`). Дефолт: `off` (спрашивать).
- FR-14 История: хранится вся переписка чата в SQLite. В агента отдаются последние 50 сообщений как контекст. `/new` — очистить историю чата. Каждый Telegram-чат = отдельная сессия (свой агент, модель, проект, история).

## 3. Нефункциональные
- NFR-1 Запуск на Windows-ПК: `npm i`, заполнить `.env`, `npm run dev` — бот отвечает `/start` с телефона.
- NFR-2 `npx tsc --noEmit` чистый, eslint чистый.
- NFR-3 Таймаут задачи 45 мин (`TASK_TIMEOUT_MS=2700000`), настраивается.
- NFR-4 Логи (`bot.log`) без секретов: токены, ключи, промпты целиком в лог не пишутся (только первые 120 символов в debug).
- NFR-5 Падение провайдера не роняет бота; ошибка → `E_AGENT_FAILED` в чат.
- NFR-6 Docker опционально (позже, для VPS): `docker build . && docker run --env-file .env` работает.
- NFR-7 Дефолтный агент — `opencode`.

## 4. Приёмка (smoke)
1. `npm run dev`, в ТГ `/start` → ответ с именем агента.
2. `/ask 2+2` на `mock` → ответ.
3. Переключить `/agent mock`, `/code напиши hello` → ответ кусками/стримом.
4. `/cancel` во время длинной задачи → `cancelled`.
5. Убить CLI (если opencode установлен) → бот жив, в чат `E_AGENT_FAILED`.

## 5. Вне scope v0.1
Голос, inline-кнопки approve (пока текстовый `/approve`), вебхук-режим (работаем на long-polling — для домашнего ПК проще и без белого IP), групповые чаты с ролями. Это v0.2.

## 6. Решения владельца (зафиксировано 27.09.2026)
- Стек: Node 20 + TS + grammy (решение инженера).
- Личный бот, whitelist по `ALLOWED_CHAT_IDS`.
- Дефолт: `opencode`. Таймаут 45 мин.
- Стриминг живым редактированием сообщения.
- История: вся, `/new` для сброса, последние 50 сообщений — в контекст агенту.
- Проекты: локальные папки + `/clone` с GitHub, привязка чата через `/project`.
- Shell: `/auto off` по умолчанию (спрашивать).
- Запуск: домашний ПК (Windows), код в GitHub.
- Токен бота: ещё не создан — получить у @BotFather (инструкция в README).
